# Linking a project on any machine

The contexts folder is shared by Syncthing. Every device — including the home
server itself — is just a client of that folder, and its local path is
whatever you chose when you added the folder in Syncthing. Nothing discovers
that path: you state it once.

    export BRAIN_CONTEXTS=/path/to/your/synced/contexts   # add to your shell rc
    brain-link.sh <project-slug>                          # run inside the repo

That creates `.brain/` in the repo pointing at the project's context folder,
writes the agent contract into `AGENTS.md` and `CLAUDE.md`, and gitignores the
symlink. Re-running is safe; it replaces only its own marked block.

Run it on as many machines as you like for the same project. Everything any of
them writes into `.brain/captures/` lands in the same synced folder, and the
home server is the only thing that reads it.

## Agent tool permissions

Agents need read access outside the repo to follow the `.brain` symlink. For
Claude Code, in your settings:

    "additionalDirectories": ["<your BRAIN_CONTEXTS path>"],
    "permissions": { "allow": [
      "Read(//<your BRAIN_CONTEXTS path>/**)",
      "Edit(//<your BRAIN_CONTEXTS path>/**/captures/**)"
    ]}

Grant write only to `captures/`. `STATE.md`, `tasks.json` and `CLAUDE.md` are
generated by the brain and overwritten.

## If captures never appear on the board

`BRAIN_CONTEXTS` points at a folder Syncthing is not actually sharing — most
likely a stale copy left behind when the server's data moved. Check the path
against the folder Syncthing lists on this device.
